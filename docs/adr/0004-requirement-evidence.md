# ADR 0004: Requirement-level evidence for the local reference

Status: proposed for independent review; not an implementation or certification approval.
Author: senior plan/design author, GPT-6.1 Sol at high reasoning. Baseline: 9fd7dbbc5cef135007b7f2253aba24c825386954.
Scope: CON-001/002/004 for local-fake-single-tender-0.1. Requirements and case meanings remain in the [extension register](../../specification/0.1.0-draft/README.md) and [CT matrix](../simulator-and-conformance.md).

## Problem, priority and decision

The current runner records stage exits, Java suite counts and explanatory CT strings. Those are useful execution evidence, but a green stage does not identify which requirement assertion passed. A renamed, missing, skipped or stale test must not silently preserve a coverage claim. Raw test output is also unsuitable for a shareable payment evidence report.

Implement a versioned observation inventory, CT-to-obligation mapping and closed machine-readable report. Collect actual named results from existing test frameworks; retain source/version/artifact identity and explicit gaps. Keep certificationVerdict exactly NOT_CERTIFIED. This slice changes evidence/test tooling and adds bounded event/privacy negatives; it introduces no new payment behavior, production ingress, dependency, migration or conflict-normalization design.

Plan priority is evidence integrity first, then targeted CT-006/010 regressions and their reviewed mapping. Broader provider execution, native AP2 verification, certification policy and managed operations remain later work. Do not delay this local slice for provider accounts or public licensing; neither is needed to measure current synthetic behavior. Do not mark those later objectives complete from this slice.

Proposed source artifacts, to create only after design acceptance:

It need not enumerate every test in a large suite. Unmapped results contribute safe counts, never requirement credit. |
| specification/0.1.0-draft/evidence/mapping.json | requirement-map-0.1: exactly CT-001 through CT-012 once each, linked EXT ID, selected profile/subset, required obligation IDs, referenced observation IDs, explicit open gap IDs and exclusions with fixed reason codes. |

An observation ID names a reviewed assertion scope, not an arbitrary test title. Changing its assertion meaning requires mapping/inventory revision and review even if a Java method name stays unchanged. A rename requires an explicit selector update; never guess a replacement by substring, fuzzy match, class count or suite exit. No wildcard selector may satisfy an obligation. The collector proves execution/outcome under a source identity; it cannot mechanically prove that the test's assertions satisfy a CT. That meaning comes from the reviewed mapping. A test may support several observations/CTs only when that mapping identifies the distinct assertions; duplicating a PASS cannot invent additional coverage.

The mapping is declarative data, never executable code, shell text, import expressions or an arbitrary path/URL. Paths resolve under named repository/run roots; reject traversal, symlink escape and external schema retrieval. Preflight rejects duplicate CT/observation/obligation IDs, unknown versions/profiles/EXT or CT references, unknown observations, empty mandatory inventories, conflicting selectors, inconsistent counts and unsupported policy fields.

### Fresh producers and minimum inventory

Create a new .tools/conformance/<runId> before any child starts, with separate raw and safe artifact directories. Keep these outside target so Maven clean cannot erase or lock them. Reserve empty stage-specific output locations and generate a stage execution nonce/receipt. The collector binds artifacts to that exact stage execution and before-source digest; timestamps alone are not freshness proof. Never search old target directories or take the newest matching report. Child failure, missing completion, missing reports or wrong run/stage/source binding prevents qualified PASS.

For selected parameterized Java names such as refusesNonCanonicalMoney(String)[n], inventory every credited invocation separately with exact cardinality. Do not collapse a method to PASS when one invocation failed/skipped, or publish argument-expanded names. Unmapped tests are represented only by bounded outcome counts, with no requirement credit or untrusted name. A missing renamed selected test still becomes INCOMPLETE even if an unmapped replacement passes. New observations require explicit review and inventory update; ordinary additional unmapped tests do not require enumerating the whole suite.

CLI demos, adapter TCK JSON and replay reports may be supplementary artifacts, with their versions/digests and actual outcomes. They cannot replace the named test inventory or prove requirements outside their reviewed scope. No stdout substring establishes a passing observation.

### Outcome derivation and report validity

Keep three different facts separate:

1. observedStatus records a named framework outcome, such as PASS, FAIL, ERROR, SKIPPED or MISSING.
2. qualifiedStatus is PASS, FAIL or INCOMPLETE after current-run/stage/artifact/source validation. A named PASS in partial XML from failed Maven is diagnostic only and becomes INCOMPLETE, never qualifying evidence. An actual named failure remains visible; stage failure never erases it.
3. coverageStatus is the CT/obligation assessment, derived from qualified observations and reviewed gaps, not copied from stage success.

Precedence for an applicable obligation/CT is FAIL, then INCOMPLETE, then PASS. A missing, skipped, expected-failure, not-executed or unavailable mapped assertion is INCOMPLETE; unexpected success is FAIL. A failed applicable mapped assertion is FAIL. PASS requires every mandatory observation to qualify, all expected invocation counts to match and no open mandatory gap. Open gaps are named versioned obligations with scope/reason/review references; there is no reporter-generated complete boolean or operator override to clear them. Closing/removing a gap changes reviewed mapping semantics and requires new review evidence.

NOT_APPLICABLE is a separate scoped result, never a substitute for missing tests. It requires an explicitly unadvertised optional profile/capability and the reviewed exclusion reason. CT-008 may be NOT_APPLICABLE for voucher/partial funding only while baseline split/underfunding-refusal observations remain mandatory. For CT-008, a failed mandatory baseline guard makes the row FAIL; missing/skipped guard evidence makes it INCOMPLETE. NOT_APPLICABLE is allowed only after those guards qualify and the optional capability remains absent. Advertising that optional profile invalidates the exclusion. CT-005 covers synthetic challenge only here; it grants no real 3DS/2FA/bank-action pass.

Execution previewChecks may remain PASS when all required stages and their selected inventories are valid but CT gaps remain. coverageStatus still reports INCOMPLETE and certificationVerdict remains NOT_CERTIFIED. Missing selected observations, invalid producers, stage failures or source mutation fail preview/evidence acceptance. Unmapped passing tests cannot repair those failures. The existing require-certification mode always returns nonzero for this slice. Global green must never synthesize CT PASS or remove a remaining certification obligation.

The report validator recomputes qualified/coverage statuses and checks exact CT completeness, required evidence relationships, count arithmetic, optional-profile eligibility, source equality and fixed certification verdict; validating JSON shape alone is insufficient. A forged report changing an observation/CT verdict without matching evidence must fail validation.

The evaluation boundary is evaluate(currentRunReceipt, producerArtifacts, inventory, mapping, schemas); verification of a report receives those same trusted input locations and recomputes the result, rather than trusting observedStatus/qualifiedStatus copied inside report JSON. Check each producer artifact's format, hash and current run/stage association against the orchestrator-owned receipt. Report-only offline validation can establish shape/internal consistency, not authentic execution; without required inputs it cannot qualify claimed PASS. A local actor replacing the complete unsigned receipt/artifact/source set is outside this local provenance claim; hashes are not signatures or accreditation.

Any actual test failure/error or unexpected success fails its stage even if that test is unmapped. A selected skip/expected failure is INCOMPLETE and fails selected-evidence acceptance. Unmapped skips/expected failures remain visible aggregate counts, receive no coverage credit and retain the framework's stage exit semantics; they cannot hide a selected missing/skipped observation. A required whole stage not executed or discovering zero tests is INCOMPLETE. Unexpected selected cardinality/duplicate match is invalid evidence rather than a silently chosen result.

### Identity, startup failures and publication

Retain exact extension/contract/profile, inventory/mapping/schema versions and hashes; canonical global POSIX source manifest before/after; selected tool/runtime versions and dependency-lock hashes; build artifact/report hashes; stage execution/run IDs and counts. Include separate hashes for the EXT register, CT-definition document and accepted design/review artifact: current source_identity does not cover all those documentation semantics. The acceptance reference names an actual external review record/date/decision; the reporter cannot create reviewer approval or a signature.

Schema/mapping changes during execution invalidate evidence just like source changes. The report identifies evidence input artifacts by opaque safe ID, format and SHA-256, with generated bundle-relative paths only. No absolute machine paths, credentials, connection strings, command environment, raw mandate/JWS/payment payload, test parameters, exception text or unrestricted assertion strings belong in the shareable report. Reason codes, observation/obligation IDs and safe invariant keys come from reviewed allowlists.

Start each run with a fresh current-run receipt; invalidate the prior default report/pointer before doing work. Preserve earlier runs in their own archives. Missing Maven/npm/database configuration, stage launch errors and timeouts must produce a current schema-valid INCOMPLETE record when schema/mapping can be loaded safely. Invalid schema/mapping produces a fixed nonzero preflight failure and no consumable current report. An old report.json must never remain discoverable as this run's result. Publish the validated safe report atomically and update its current pointer only with the matching run ID; consumers/CI must check that association, not file existence alone.

Raw diagnostics may contain synthetic canaries or traceback/system output. Retain them only as ignored, unreviewed local diagnostics; never automatically copy them into the safe evidence bundle or publish them as sanitized. Hashes/opaque references may identify them without exposing content. Existing raw-log copying must be removed from the shareable output or explicitly segregated outside it. Report/schema validity alone proves neither product logging privacy nor every CT-010 sink.

CI must replace the current failed-log tail step with a validated fixed safe summary of stage/observation IDs, statuses, counts and reason codes. It must not print raw logs, XML failure/system output, Python tracebacks or unrecognized test names to hosted output. Upload only the validated safe report/bundle for the current receipt; missing/invalid evidence yields a fixed failure summary instead of dumping diagnostics. Keeping logs outside the artifact while still tailing them to CI would not satisfy this boundary.

## Acceptance tests and delivery order

1. After independent design acceptance, implement schemas, semantic validator and executable fixtures first. A valid fixture deliberately has passing observations and INCOMPLETE CT rows; another proves legitimate optional CT-008 exclusion with baseline refusal evidence.
2. Negative report/mapping fixtures must reject: missing/duplicate CT, unknown logical IDs/version, duplicate/ambiguous selected selectors, missing required observation, false N/A, absent capability declaration, forged PASS, removed open gap, bad counts/digest/path, arbitrary secret/error field, changed source, malformed XML/DTD, stale run nonce, old reports and unsupported format. Corrupt or skip one selected test in an otherwise green fixture and verify INCOMPLETE plus nonzero evidence acceptance, without fabricating application failure. Unmapped runtime names are safe counts, not invalid logical IDs or new credited observations.
3. Collector tests cover framework edge cases: Java skipped/parameterized missing invocation/error; Python subtest failure, skip, expectedFailure/unexpectedSuccess, import/load/setup/teardown errors and zero discovery; Node failed build, duplicate title/skip/unknown XML shape; fixture expected-refusal inversion. Include stage-failed-but-named-PASS and interrupted sidecar completion cases.
4. Implement the bounded CT-006/010 tests independently of the reporter author; update inventory/mapping with exact names only after source review. Synthetic canary-bearing malformed producer artifacts must either be rejected/quarantined or normalized into safe reason codes; the shareable report/bundle must contain no canary/raw error text.
5. Run the normal unchanged-source aggregate against PostgreSQL, validate the final report semantically and against its schema, and independently review source/mapping/evidence. Preserve actual counts and remaining gaps. Check that deleting/renaming/skipping an inventoried test or substituting an earlier report cannot preserve a requirement claim.
